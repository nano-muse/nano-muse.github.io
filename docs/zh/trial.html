一个账号，所有设备 ​

在手机、电脑和网页控制台上登录同一个账号，它们就成了一体：在一台设备上说，事情在另一台 上做完；审批问题回到你打字的那台设备；主要聊天跟着你走。这一页在公共中继 cloud.nanomuse.cn 上从一部新手机走到「手机让 Mac 编译项目」。协议见 hub.md， 账号和免费额度见 cloud.md，自己的中继见 self-hosting.md。

1. 手机 ​

安装 App（android.md、ios.md）。第一屏就是账号：手机号或邮箱加一个 验证码，设过密码后用密码。这一次登录同时配好 nanoMuse Cloud 服务商、设置 → 模型的四行，以及 与其他设备的连接。

手机这一侧在 设置 → nanoMuse Cloud → 设备：「让其他设备能找到这台手机」让手机保持连接， 其他设备才能找它做事（开着时有一条安静的通知）；「允许其他设备操作这台手机」决定它们能不能在 这里跑 shell 命令、读文件、截屏或交一个任务过来，关掉后这台手机仍然看得见、也能操作其他设备； 「这台手机的名字」是你会说出口的词，短一点：「pixel」「小米」。下面的列表是账号下的每台设备， 在线的，或上次出现的时间。

iPhone 以 iOS 允许的方式参与：它响应 info、open、notify 和 task；shell、文件和屏幕在 iOS 上没有。

2. 电脑 ​

从最新版本安装 nanoMuse 桌面版 （desktop.md：每个平台一个安装包，手的运行时在里面），用同一个账号登录。几秒之内 电脑出现在手机的设备列表里，手机出现在桌面版侧栏的「设备」页里。在 设置 → 设备 给电脑起个名字 （「mac」「desk」）。

另一台设备要操作这台电脑之前，电脑先问：屏幕上一张卡片，「允许一次」或「对那台设备总是允许」。 设置 → 设备 里的「免询问远程控制」对账号下的每台设备都关掉这张卡片。

只跑 Python 运行时的电脑（nanomuse serve，网页版登录同一个账号）也以同样的方式加入 （app.md、cli.md）。

3. 网页控制台 ​

https://cloud.nanomuse.cn/app/，同一个登录。它显示账号的设备和对话；选一台设备，打字，审批以 卡片出现。你自己的中继在它的 /app/ 下提供同一个控制台。

4. 试一试 ​

在手机上：「在 mac 上列一下下载文件夹」「让 desk 把 ~/proj 编译一遍，把最后二十行日志发我」 「电脑截个图给我看」「给电脑发个通知：该睡了」

在电脑上："on the phone, take a screenshot"、"tell pixel's Muse to read me the last notification"、"send pixel a notification: build finished"。

在控制台里：选一台设备，打字。

一整件用话说出来的事（「把项目编译一遍，把日志发我」）会作为任务在另一台设备自己的 Muse 里跑， 在一个单独的对话里，可能要几分钟；步骤会随做随显示在你的聊天里。

5. 审批 ​

删除、发送、付款、动系统的事都先问，在你打字的那台设备上问；远端 Muse 的审批问题也以同样的方式 回到你这里。从一台设备操作另一台是第二个问题，问的是拿着那台设备的人（上面第 1、2 节）。那边 没人，发起方就会听到「未被允许」。

6. 跟着你走的东西 ​

登录后，主要聊天和旁聊跟着你到其他设备；每台设备的「数据控制」可以把它关掉（sync.md）。 智能体的名字和形象属于账号。在一台设备上登录过的连接器，在其他设备上显示为「已在〈设备〉上连接」， 一步就能在那里也登录（hub.md）。模型按设备各选各的：每台的 设置 → 模型 是它自己的。

7. 自己的中继 ​

self-hosting.md 在一台小 VPS 上跑同一个中继。手机在登录页的「使用其他服务器」 填它的地址；nanoMuse 桌面版在桌面配置的 cordis.patch.yml 里填；控制台就是提供它的那个中继的 /app/。同一个账号下的每台设备必须指向同一个中继，因为设备和对话都在那里。
