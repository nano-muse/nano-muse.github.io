nanoMuse 品牌 ​

2026-09-24 定稿。应用图标和应用内的配色体系是同一个决定：调色板由图标推导出来，这样整个应用 才会和主屏幕上的那块图标是一个样子。

标志 ​

一笔连续的笔画，读出来是一个 N：带钩的起笔、一个圆峰、一条长斜线、一个收紧的谷、向上的收笔。 它和 Muse 的单笔标志遵循同一套视觉语法（Muse 的是三个拱的 M，我们的是一个拱的 N）——就像 OpenManus 和 Manus 押韵，却是另一个手势。标志刻意做得抽象：它先是一个手势，然后才是一个字母。

  • 源文件只有一个：assets/brand/nanomuse-icon-source-1024.png（最终渲染，品牌蓝底上的白色圆角方块）。 其余一切都由它派生。
  • assets/brand/nanomuse-mark.svg——只有笔画本身，描成一条填充路径，viewBox 0 0 100 100，用方块坐标，渐变填充。
  • assets/brand/nanomuse-icon.svg——白色圆角方块（rx=27）加标志。这就是应用图标。
  • assets/brand/nanomuse-icon-on-blue.svg——放在品牌蓝背景上的图标，只用于商店页面和启动页。 凡是用图标代表这个应用的地方——README、网站、社交卡片、favicon——都用素净的那块：白底、标志、 一道细边，没有背景。
  • assets/brand/nanomuse-mark-rgba-688.png——带透明通道的笔画，688 px，位图兜底。
  • docs/app-icon.png——带圆角渲染出来的方块（27 % 圆角半径，外侧透明，一道 #D9D9DE 细边， 放在白底上也保得住形状），512 px：图标在主屏幕上的样子。它是 README 的头图，也是任何把 nanoMuse 当作一个 App 展示的地方该用的那张图。

图标不是吉祥物。默认的脸是随附的小龙（web/public/avatars/，Android 应用的 avatar/）； 其他可选的是一个放在色块上的 emoji，或在形象工作室里做出来的一张脸。早期版本的小熊猫在 0.1.23 退役了。 永远不要把小龙（或过去的小熊猫）放到启动器图标上，也永远不要把 N 标志放进聊天里当一张脸。

颜色 ​

从图标上量出来的。

令牌值用途
brand.stroke.start#015CFB标志渐变的左端
brand.stroke.end#0186FB标志渐变的右端
brand.blue#0078FD方块背后的背景；启动页；头图背景
tile#FFFFFF图标方块

浅色主题 ​

令牌值对比度用途
primary#015CFB白底上 5.35链接、主按钮（白字）、当前标签、发送按钮、状态行
primary.container#E5F0FF—用户气泡、选中的行、标签
primary.tint#EEF5FF—轻微高亮的表面
bg.grouped#F2F2F7—页面背景（沿用 OpenMinis，没有改）
surface#FFFFFF—卡片、输入框

深色主题 ​

令牌值对比度用途
primary#58A6FF#000 上 8.3，#1C1C1E 上 6.7链接、按钮（黑字）、当前标签、状态行
primary.container#1A2B4A—用户气泡
bg / surface / surface.2#000000 / #1C1C1E / #2C2C2E—沿用 OpenMinis，没有改

规则：强调色只有一个色相。OpenMinis 用 iOS 的蓝、橙、绿着色的代码块、思考文字和链接，一律改成 primary 加中性色。小熊猫身上的铁锈橙留在形象里；它不是界面颜色。

Android 映射（S1 已完成） ​

  • 自适应图标：背景层 = 纯色 #FFFFFF；前景层 = 标志，一个 VectorDrawable，fillColor 是上面那个 两档线性渐变；单色层 = 同一条路径，平涂填充（由 Android 着色）。
  • 图标皮肤（从 OpenMinis 保留下来的 activity 别名）：自动 = 白色方块；浅色 = 白色方块； 深色 = #0F1B33 方块加白色标志。
  • 通知小图标：标志，平涂白色，24 dp。
  • 永远不要发布旧的 OpenMinis 图标、名字，或者字母 n 的那些草稿。

不要这样做 ​

  • 不要把标志涂成蓝色渐变、平涂白、平涂黑以外的颜色。
  • 不要旋转、描边，也不要给笔画加阴影。
  • 不要把标志直接放在品牌蓝上而不垫白色方块（对比度不够）。
  • 不要把 Meta 的 Muse 标志、名字或蓝色当作素材；亲缘关系只在手势上。
